# SWILL Project - Техническая документация

## Обзор архитектуры

SWILL (Stealthy Windows Injection & Low-level Loader) состоит из двух основных компонентов:

### 1. SWILL_Loader (Инжектор)
- **Назначение**: Внедрение DLL в целевой процесс
- **Архитектура**: x86 (32-bit)
- **Зависимости**: Windows API (kernel32.dll, advapi32.dll)

### 2. SWILL_Payload (DLL ядро)
- **Назначение**: Сигнатурный анализ, перехват функций, обход античита
- **Архитектура**: x86 (32-bit)
- **Зависимости**: MinHook, Windows API, Psapi

## Детальная спецификация сигнатур

### Сигнатуры CIdArray

#### 1. CIdArray::PopUniqueId (FUN_10241990)
**Основная сигнатура:**
```
55 8B EC 83 EC ?? 53 56 57 A1 ?? ?? ?? ?? 33 C5 89 45 F4 8B 1D
```

**Альтернативная сигнатура:**
```
55 8B EC 6A FF 68 ?? ?? ?? ?? 64 A1 00 00 00 00 50 83 EC ?? 53 56 57
```

**Назначение:** Выделение уникального ID для нового объекта
**Возвращаемое значение:** Закодированный ID (индекс + 0x2000000)
**Параметры:**
- param_1: Указатель на объект
- param_2: Тип объекта (класс)

#### 2. Ловушка краша (Hard Crash Trap)
**Сигнатура:**
```
C7 05 00 00 00 00 00 00 00 00
```

**Описание:** Инструкция `mov dword ptr [0], 0` которая вызывает исключение доступа к памяти
**Метод обхода:** Замена на 10 байт NOP (0x90)

#### 3. Обработчик дампов (Watson Handler)
**Сигнатура:**
```
FF 15 ?? ?? ?? ?? 8B C5 5F 5E 5B 8B E5 5D C3
```

**Описание:** Вызов функции создания дампа при ошибке

## Карта памяти CIdArray

### Глобальный управляющий блок (база: 0x105c8b58)

| Смещение | Размер | Поле | Тип | Описание |
|----------|--------|------|-----|----------|
| 0x00 | 4 | m_uiCapacity | uint32 | Максимальная ёмкость массива |
| 0x04 | 1 | IsInitialized | uint8 | Флаг инициализации (0/1) |
| 0x05 | 3 | Padding | - | Выравнивание |
| 0x08 | 4 | m_uiPopIdCounter | uint32 | Счётчик операций PopUniqueId |
| 0x0C | 4 | m_uiTimeoutLimit | uint32 | Лимит времени (3600000 мс) |
| 0x10 | 4 | m_IDStackCapacity | uint32 | Ёмкость стека свободных ID |
| 0x14 | 16 | Reserved | - | Зарезервировано |
| 0x24 | 4 | m_IDStackCount | uint32 | Текущее количество свободных ID |
| 0x28 | 4 | m_ArrayData | uint32* | Указатель на данные массива |
| 0x2C | 4 | m_ArrayEnd | uint32* | Указатель на конец массива |

### Структура элемента массива (8 байт)

| Смещение | Размер | Поле | Описание |
|----------|--------|------|----------|
| 0x00 | 4 | pObject | Указатель на объект или хэндл |
| 0x04 | 4 | classId | Идентификатор типа объекта |

### Типы объектов (classId)

| ID | Тип | Описание |
|----|-----|----------|
| 1 | Account | Учётная запись |
| 2 | ACL | Список контроля доступа |
| 3 | Resource | Ресурс MTA |
| 4 | Timer | Таймер |
| 5 | Vector3 | Вектор (3 компонента) |
| 6 | Matrix | Матрица трансформации |
| 7 | Element | Элемент игрового мира |
| 8 | Player | Игрок |
| 9 | Vehicle | Транспортное средство |

## Алгоритмы работы хуков

### Hooked_PopUniqueId

```
1. Проверить флаг IsInitialized
   └─ Если 0: вызвать оригинальную функцию
   
2. Прочитать m_IDStackCount
   └─ Если <= 0: сгенерировать виртуальный ID
       ├─ fakeIndex = m_uiCapacity + 1000
       └─ return fakeIndex + 0x2000000
   
3. Вызвать оригинальную функцию
4. Вернуть результат
```

### Нейтрализация ловушки краша

```
1. Найти паттерн C7 05 00 00 00 00 00 00 00 00
2. Изменить защиту страницы на PAGE_EXECUTE_READWRITE
3. Записать 10 байт 0x90 (NOP)
4. Восстановить защиту страницы
5. Очистить кэш инструкций
```

## Обработка ошибок

### Коды ошибок MinHook

| Код | Константа | Описание |
|-----|-----------|----------|
| 0 | MH_OK | Успех |
| 1 | MH_ERROR_ALREADY_INITIALIZED | Уже инициализировано |
| 2 | MH_ERROR_NOT_INITIALIZED | Не инициализировано |
| 3 | MH_ERROR_ALREADY_CREATED | Хук уже создан |
| 4 | MH_ERROR_NOT_CREATED | Хук не создан |
| 5 | MH_ERROR_ENABLED | Хук включен |
| 6 | MH_ERROR_DISABLED | Хук выключен |
| 7 | MH_ERROR_TOO_MANY_HOOKS | Слишком много хуков |
| 8 | MH_ERROR_INVALID_CALL | Неверный вызов |
| 9 | MH_ERROR_MEMORY_ALLOC | Ошибка выделения памяти |
| 10 | MH_ERROR_MEMORY_PROTECT | Ошибка защиты памяти |
| 11 | MH_ERROR_UNSUPPORTED_FUNCTION | Функция не поддерживается |
| 12 | MH_ERROR_BAD_POINTER | Неверный указатель |
| 13 | MH_ERROR_INVALID_PARAMETER | Неверный параметр |

### Стратегии восстановления

1. **При ошибке инициализации MinHook**: Продолжить работу без хуков
2. **При ненайденной сигнатуре**: Логировать предупреждение, продолжить поиск других паттернов
3. **При краше в хуке**: Использовать SEH (Structured Exception Handling)

## Безопасность и скрытность

### Меры предосторожности

1. **Минимальные права доступа**: Использование PROCESS_VM_OPERATION | PROCESS_VM_WRITE | PROCESS_CREATE_THREAD вместо PROCESS_ALL_ACCESS

2. **Восстановление защиты памяти**: После патчинга восстанавливаются оригинальные флаги защиты страниц

3. **Очистка кэша инструкций**: Вызов FlushInstructionCache после модификации кода

4. **Отсутствие следов в памяти**: Очистка пути к DLL после загрузки

### Уязвимости и ограничения

1. **ASLR**: Адреса вычисляются динамически через сигнатуры
2. **Обновления игры**: При изменении бинарного файла сигнатуры могут устареть
3. **Антивирусы**: Инъекция DLL может детектироваться как подозрительное действие

## Расширение функционала

### Добавление нового хука

1. Определить сигнатуру функции в Ghidra/IDA
2. Добавить паттерн в Core.cpp
3. Создать функцию-детур с правильной сигнатурой
4. Зарегистрировать хук через SwillHooks::EnableHook
5. Сохранить указатель на оригинальную функцию

### Пример добавления хука на FreeSlot

```cpp
// 1. Объявление типа функции
typedef void (__stdcall *TFreeSlot)(unsigned int encodedId);
TFreeSlot g_OriginalFreeSlot = nullptr;

// 2. Функция-детур
void __stdcall Hooked_FreeSlot(unsigned int encodedId) {
    SWILL_LOG("FreeSlot: " + std::to_string(encodedId));
    g_OriginalFreeSlot(encodedId);
}

// 3. Регистрация в SwillCoreThread
uintptr_t freeSlotAddr = FindFreeSlotFunction(hNetc);
if (freeSlotAddr) {
    SwillHooks::EnableHook(
        (void*)freeSlotAddr,
        (void*)Hooked_FreeSlot,
        (void**)&g_OriginalFreeSlot,
        "CIdArray::FreeSlot"
    );
}
```

## Отладка

### Логирование

Файл лога: `swill_payload.log`

Формат записи:
```
[HH:MM:SS.mmm] [LEVEL] Сообщение
```

Уровни логирования:
- SUCCESS: Успешное выполнение операции
- WARNING: Предупреждение (не критично)
- ERROR: Ошибка (требуется внимание)
- INFO: Информационное сообщение

### Консоль отладки

При инъекции открывается консоль с выводом:
- Статус инициализации компонентов
- Найденные адреса функций и структур
- Статус установки хуков
- Периодические отчеты о состоянии
